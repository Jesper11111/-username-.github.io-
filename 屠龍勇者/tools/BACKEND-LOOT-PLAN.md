使用者已選「先搬線上打怪、首領與副本；離線掛機另議」，並明確同意製作後端SQL與遊戲串接。20261022t已實作並完成本機隔離測試；尚未修改正式Supabase。實際部署、分工及限制以SERVER-LOOT.md為準；原盤點保留供後續完整權威後端改造參考。

## 現有入口

| 入口 | 現在的責任 | 搬移時要涵蓋 |
|---|---|---|
| combat.js onKill／rollDrops | 本機結算擊殺、金幣、一般掉寶 | 通用／地區／怪物掉落、首領材料、數量、隨機裝備 |
| affix.js rollQuality／applyAffixes | 本機抽裝備品質、詞綴及數值 | 後端產生完整裝備結果，不讓前端重抽 |
| craft.js rollCurrency | 製作通貨抽選 | 與同次擊殺獎勵一起記錄 |
| maps.js rollMapDrop／giveMap | 異界地圖及其隨機屬性 | 地圖階級、品質、詞綴、異界首領固定獎勵 |
| spellbook.js rollBookDrop | 高級技能書抽選 | 依怪物等級篩選的書池 |
| quests.js questOnKill | 任務收集物另行抽選 | 任務資格、需求數量上限與進度 |
| raid.js raidApplyReward | 各玩家瀏覽器各抽一次副本掉寶 | 後端以場次、參加者、角色去重，不能沿用只靠本機raidRuns |
| vault.js diaRoll／dia_drop | 前端判斷是否掉鑽石，後端管理餘額／每日上限 | 若包含鑽石掉落，擲骰及資格一併改；保留登入獎勵 |
| offline.js measureHunt／applyOffline | 前端試算經驗、金幣、消耗品；目前不交付道具 | 若新增離線掉寶，必須另做後端時間、補給與結算驗證 |

世界首領還有既有wb_claim獎勵路徑，需檢查是否納入共同獎勵帳本，不能只替換rollDrops就宣稱全部完成。

## 建議的交付流程

1. 登入後由後端建立狩獵／副本場次，綁定帳號、角色及規則版本；怪物與獎勵參數由後端資料查出。不能相信前端傳入的掉率、裝備清單、等級、boss旗標、獎勵倍率或擊殺數。
2. 後端核對場次、資格、伺服器時間與結算序號。每次事件只產生一份獎勵；重送同一序號回傳原結果，不再次擲骰。一般狩獵需補擊殺資格驗證；只把亂數搬到伺服器不能證明玩家真的打死怪物。
3. 後端決定物品、數量、品質、完整詞綴，保留目前掉率與物品池。獎勵帳本先記結果，再交付；斷線後按原結果補領。
4. 背包交付與已領狀態要在可驗證的交易中處理。沿用目前「前端寫整份背包再上傳」不能保證道具不被偽造／複製；需要權威道具來源與異動記錄，並處理舊版整份存檔覆蓋。
5. 戰利品過濾、自動賣出、負重滿不撿、地圖／任務上限要保留原行為；涉及自動賣出所得的金幣也必須一起確認，不能另由前端填任意金額。
6. 斷線時不退回本機抽獎。尚未接受的事件不能承諾補發；已由後端接受的獎勵可按帳本補領。訪客模式的物品是否可進正式帳號／交易所需明確規則，避免繞過後端掉寶。

## 已決定範圍及後續界線

- 範圍已選線上打怪／首領／副本，不新增離線道具。正式SQL製作已授權，由使用者自行部署。
- 金幣／經驗是否也要由後端結算：本次原始要求是掉落物品，不自行擴大為整套戰鬥重寫。
- 訪客及斷線狩獵政策、舊道具如何保留與遷移。
- 依AGENTS.md第3節，修改正式資料庫SQL前要確認，SQL由使用者貼到Supabase執行；若需新增player收據等欄位，也要依第2節第6點確認schema遷移。

## 驗證與啟用條件

- 本機隔離資料庫：未登入／跨帳號／錯角色／非法地區／假boss／超速或重複擊殺／過期場次／重複結算，均不能增加獎勵；合法重試回原結果。
- 同時請求、斷線、重登、切角色、重新整理、多裝置與舊版存檔上傳，不重抽、不重複交付、不覆蓋已領物品。
- 比對現有各種怪物、塔層、異界加成、任務、副本及裝備詞綴規則；負重／自動賣出與掉落紀錄一致。
- 保留舊存檔與原道具，先提供遷移及驗證，再按新版本切換；前後端需一起啟用，不能先讓正式遊戲呼叫尚未部署的RPC。
- 執行check.ps1、相關回歸與瀏覽器實玩；使用者確認後才commit及請Push origin。
